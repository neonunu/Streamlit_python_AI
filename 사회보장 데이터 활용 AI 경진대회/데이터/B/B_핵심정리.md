## 1. 일반 프로그램이 하는 일 vs AI가 하는 일

| 일반 프로그램 (규칙) | AI (LLM) |
| --- | --- |
| 기관 데이터 조회, 지역 필터 (같은 동 → 같은 시군구) | 부모가 자유롭게 쓴 글에서 조건 5개 추출 (나이, 치료 영역, 아이 특성, 가능 시간, 지역) |
| 비교표 칸 채우기, 출처 표시 | 확인 안 된 항목을 기관별 전화 확인 질문으로 바꾸기 |
| 품질등급은 부모 화면에 보이지 않게 내부에서만 사용 | 후보를 고른 이유를 쉬운 말로 설명 (데이터에 있는 내용만) |
| 확인 결과 저장·집계 | — |

- **2029년 추세는 AI가 아니다.** C의 단순 선형추세는 통계 분석이다. AI 혁신은 자연어 조건 추출, 확인 질문 생성, 근거가 표시된 후보 설명에 있다.

## 2. 작동 순서

1. 부모가 아이 상황을 말로 입력
2. AI가 조건 5개를 표로 추출 → 부모가 확인·수정
3. 프로그램이 실제 바우처 기관 중 후보 최대 3곳을 고름 (같은 동 먼저)
4. 비교표: 정보마다 `[확인됨]`·`[추정]`·`[확인 필요]` 표시
5. AI가 기관마다 전화 확인 질문 3개 생성
6. 첫 상담 체크리스트 제공 (바우처·본인부담금, 치료 분야, 치료사 자격·경력, 운영시간, 대기, 결석·보강, 상담·평가 주기)

## 4. AI가 확인되지 않은 정보를 만들지 않게 하는 규칙

1. 첨부 CSV에 있는 기관만 후보로 고른다.
2. 운영시간·대기·치료사 경력은 파일에 없으면 반드시 `[확인 필요]`
3. 치료 분야는 CSV `표시` 값(`추정`/`확인 필요`)을 그대로 붙인다.
4. 부모가 치료 영역을 말하지 않으면 진단명으로 정하지 않는다 (`전문가 상담을 통해 치료영역 확인 필요`).
5. 품질등급은 순위에 쓰지 않고, 등급이 없는 이유를 추측하지 않는다.
6. 의료·치료 판단이 아니라 기관 탐색 안내임을 밝힌다.

## 5. 기존 서비스와의 차이 (제안서 4번)

| 비교 대상 | 하는 일 | 우리와 다른 점 |
| --- | --- | --- |
| 사회서비스 전자바우처 제공기관 검색 | 지역별 기관 목록, 품질평가 | 치료 분야·운영시간이 시스템에 없음 (사보원 회신으로 확인). 조건 추출·확인 질문·공백 분석은 확인하지 못함 |
| 복지로 | 복지제도 안내, 복지시설 지도 | 개별 치료실 비교·확인 질문 기능은 확인하지 못함 |
| Tio (민간 앱) | 전문가 매칭, 거리순·인기순 기관 탐색, 일정·상담 | 개인 매칭 자체는 차별점으로 주장하지 않음. 확인/추정 표시·확인 질문·지자체 공백 분석은 확인하지 못함 |
| 그로우매치 (민간 웹) | 자가진단, 치료사 개인의 자격·경력에 AI 적합도 점수, 치료 관리 | 치료사 **개인정보**를 점수화 (동의 없는 게시 논란, 복지부 검토 착수 보도 2026-11-07). 우리는 **기관 단위 공공데이터만** 씀. 경북 바우처 기관 106곳 중 바우처 표시 29곳 |

**핵심 차이 세 가지**

1. **지정 바우처 기관 366곳 전체**(정보공개청구 회신 대조)를 공공데이터로 다룬다. 민간 앱은 등록 범위·바우처 표시가 일부다.
2. **모르는 것을 숨기지 않는다.** 확인된 정보와 추정·확인 필요를 나누고 확인 질문으로 바꾼다.
3. **개인 추천이 지자체 공백 분석으로 이어진다.** 치료사 개인정보는 쓰지 않는다.
